# ADR-0004: SX1302/SX1303 concentrators only; port sx1302_hal V2.1.0

- Status: superseded by ADR-0005 (SX1301 support). The sx1302_hal port
  and the pads 31/33 check remain valid.
- Date: 2026-11-21

## Context

The bench HAT carries a MaxIIoT GL5712 card. It is an SX1301 + 2× SX1257
design (version register 0x67). The plan allows SX1302/SX1303 cards only.
Options were: (A) fit an SX1302/SX1303 card, or (B) also port Semtech's
SX1301 `lora_gateway` HAL. Upstream no longer maintains that HAL. A ChirpStack
user also failed to start two GL5712 cards on this HAT and found no cause.

## Decision

- Option A. Only SX1302/SX1303 cards are supported. The firmware identifies the
  card at boot and does not start the HAL on an SX1301.
- Port Semtech `sx1302_hal` V2.1.0 (commit 4b42025) as the
  `firmware/components/sx1302_hal` component, generated by
  `tools/import_sx1302_hal.py`:
  - Upstream frame building is kept. Only the Linux edges (spidev, sleeps,
    i2c-dev, USB, symlink) go through `port/`.
  - The temperature sensor is optional, with a fixed fallback temperature.
  - SPI runs without DMA, in polled 64-byte chunks with CS held, so there is
    no allocation per transfer.
- Exemption from the engineering rules: the upstream files build with
  `-Wno-error`, `-Wformat` off and `-Wunterminated-string-initialization` off,
  and they are excluded from clang-tidy/cppcheck. Port files are not exempt.

## Consequences

- The GL5712 cards are spares.
- The first hardware check of the port is `lgw_start` → `lgw_get_eui` →
  `lgw_stop` on an SX1302/SX1303 card (`firmware/main/conc_hal.c`).
- The HAT routes Pi UART pins 8/10 to mPCIe pads 31/33. On the P4 these are
  GPIO37/38, the console and flashing UART. Before fitting a new card, check
  its pads 31/33. A card that drives pad 33 conflicts with the CH343 on GPIO38.
